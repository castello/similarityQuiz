❯ 한글 정답에 대한 유사도 높은 힌트를 주면 사용자가 답을 맞추는 게임 만들고     
  싶은데 어떻게 할까?                                                           

⏺ 꼬맨틀 같은 게임이네요. 핵심은 정답과 추측 단어 사이의 유사도를 점수로 매기는 
  것이고, 방법은 크게 세 가지입니다.

  1. 유사도 계산 방식

  방식: 단어 임베딩 (fastText 한국어, Word2Vec)
  장점: 꼬맨틀과 같은 방식이고, 의미 유사도가 자연스럽게 나옵니다.
    오프라인에서 돌아갑니다.
  단점: 모델 파일이 큽니다(수백 MB~GB). 서버나 사전 계산이 필요합니다.
  ────────────────────────────────────────
  방식: LLM/임베딩 API (OpenAI, Voyage 등)
  장점: 구현이 쉽고 품질이 좋습니다.
  단점: 호출 비용과 지연이 있습니다. 정답 단어 하나에 대한 후보 단어 벡터를
    미리 계산해두면 줄일 수 있습니다.
  ────────────────────────────────────────
  방식: 사전 계산 랭킹
  장점: 런타임이 가볍고 빠릅니다. 정적 호스팅도 가능합니다.
  단점: 정답 단어마다 사전 작업이 필요합니다.

  2. 추천 구조 (꼬맨틀 방식)

  1. 정답 후보 단어 목록(명사 위주 수천 개)을 준비합니다.
  2. 하루에 하나씩 정답을 고릅니다. 날짜 시드를 쓰면 됩니다.
  3. 정답 하나에 대해 전체 사전 단어(예: 5만~10만 개)와의 코사인 유사도를 미리 
     계산해 순위표를 만듭니다. 이 결과를 JSON으로 저장합니다.
  4. 사용자가 단어를 입력하면 이 JSON에서 유사도와 순위(예: 1000위권 이내만
     표시)를 보여줍니다.
  5. 사전에 없는 단어는 "모르는 단어입니다"로 처리합니다.

  이 방식이면 서버 없이 정적 웹페이지로 배포할 수 있습니다.

  3. 힌트 기능

  - N위 단어 공개: 정답과 가까운 1000위, 100위, 10위 단어를 힌트로 보여줍니다.
  - 초성 힌트: 정답의 초성을 알려줍니다.
  - 유사도 그래프: 지금까지 추측한 단어를 점수순으로 정렬해서 보여줍니다.

  4. 한글 처리 팁

  - 형태소 분석(KoNLPy, Kiwi)으로 활용형을 기본형으로 정리합니다(예: "먹었다" →
    "먹다").
  - 정답은 명사로 제한하면 게임이 훨씬 자연스럽습니다.
  - 사전 단어는 국립국어원 우리말샘이나 표준국어대사전 기반 목록을 쓸 수
    있습니다.

  추천 스택

  - 프론트엔드: 순수 HTML/JS, 또는 React
  - 전처리: Python + fastText 한국어 벡터(cc.ko.300.bin) → 정답별 순위 JSON 생성
  - 배포: GitHub Pages나 Vercel 같은 정적 호스팅

  1. 형태: 웹 게임(브라우저)과 CLI 중 어느 쪽인가요?
  2. 유사도 방식: 로컬 fastText로 사전 계산(무료, 모델 다운로드 필요)과 API
     사용(간단, 비용 발생) 중 어느 쪽인가요?
